# tools/　文件字形工具（**不屬於 kit**）

這裡的兩個腳本只服務本 repo 的文件品質，**不會**被安裝到任何專案、也不参与 `frontend-devkit` 的任何 agent 執行。實作 kit 元件時不要引用它們。

| 腳本 | 用途 | 注意 |
|---|---|---|
| `normalize-forms.ps1` | 把文件中混入的簡體詞換成台灣用字；並在「漢字直接黏 `reviewer`／`developer`／`orchestrator`／`setup`」時補半形空格；表格儲存格 `|` 後直接接檔名時補空格 | ①**只做確定詞**的替換，不碰「內／制／裡」等台灣正字；②**不可使用「擴充式」替換**（例 `只准→只准許`）——`String.Replace` 不具冪等性，每跑一次多一個「許」，第 5 輪就是這樣製造出「只准許許」；③一律 `-Encoding utf8NoBOM`，避免 PowerShell 5.1/7 的 BOM 翻轉 |
| `scan-forms.ps1` | 只讀掃描：列出仍疑似簡體字形的行與行號，供人工判斷 | 有誤報（「制」「当」等在繁體是正字），必須人工逐條看過再決定是否改 |

## 使用紀律（第 5 輪的教訓，寫在這裡是因為我踩過四次）

1. 跑完任何批量替換，**必須人工重讀被改動的行**，並用 `scan-forms.ps1` 再掃一次；不可只看腳本輸出就宣稱「已清乾淨」。
2. 若用腳本改「引用／編號」，改完要 `grep` 全部引用點核對（本 repo 的 § 引用規則見 `docs/specs/*.md` 的「0. 檔案地圖」）。
3. 拆檔或改檔名後，同樣跑一次引用比對——「宣稱已修但沒修」是這份設計文件前幾輪最常見的失敗形態。
